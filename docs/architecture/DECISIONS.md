# Architecture and product decisions

This log separates decisions already justified by evidence from decisions that need Brian's approval. A decision marked `pending` must not be embedded irreversibly in production policy or infrastructure.

## Locked for the foundation

| ID      | Decision                                                                                                                                                                                                                                                                                                                                                                                                                   | Reason                                                                                                                                                                                                                                     |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADR-001 | `our-days` is a standard, single-repository Next.js App Router application deployed to a dedicated Vercel project.                                                                                                                                                                                                                                                                                                         | It preserves the approved prototype while staying on the familiar stack and leaving a clean HTTP boundary for a future native client.                                                                                                      |
| ADR-002 | Proof code, accounts, projects, secrets, data, domains, and deployment links are never reused.                                                                                                                                                                                                                                                                                                                             | Separation is an explicit product and privacy requirement.                                                                                                                                                                                 |
| ADR-003 | Server Components are the default. Client Components are limited to interactive islands such as the composer, reactions, and pagination.                                                                                                                                                                                                                                                                                   | This reduces browser code and keeps protected reads on the server.                                                                                                                                                                         |
| ADR-004 | Supabase RLS and Storage policies are authoritative. UI checks and route checks are defense in depth, not authorization.                                                                                                                                                                                                                                                                                                   | A private family app must remain safe when a route or client is called directly.                                                                                                                                                           |
| ADR-005 | Every circle-owned table carries `circle_id`, a composite uniqueness key, and composite foreign keys that prevent cross-circle ID mixing.                                                                                                                                                                                                                                                                                  | RLS alone does not create referential tenant integrity, especially for a user who belongs to multiple circles.                                                                                                                             |
| ADR-006 | `journal_person_id` and `recorded_by_user_id` are distinct.                                                                                                                                                                                                                                                                                                                                                                | A parent can preserve a child's life while attribution remains truthful.                                                                                                                                                                   |
| ADR-007 | Historic ordering uses authoritative `occurred_on date`, with optional time, timezone, and precision fields.                                                                                                                                                                                                                                                                                                               | Date-only memories must not move to another day because of timezone conversion.                                                                                                                                                            |
| ADR-008 | Pagination is cursor-based and stably ordered by occurrence fields plus `id`.                                                                                                                                                                                                                                                                                                                                              | Equal timestamps must never create duplicate or skipped moments.                                                                                                                                                                           |
| ADR-009 | Originals are immutable and checksummed. Display assets are derivatives with stripped EXIF/GPS.                                                                                                                                                                                                                                                                                                                            | Ownership and fidelity require preserving source bytes without leaking hidden metadata into normal display.                                                                                                                                |
| ADR-010 | Private media bypasses generic Next image-optimizer caching. Authenticated downloads or tightly controlled short-lived derivative URLs are used instead.                                                                                                                                                                                                                                                                   | Optimizer/CDN caches can outlive a user's access.                                                                                                                                                                                          |
| ADR-011 | The service worker, when introduced, allowlists only public versioned shell assets. It does not cache authenticated HTML, APIs, timelines, drafts, comments, locations, or media.                                                                                                                                                                                                                                          | Offline convenience must never reveal the previous account's family data.                                                                                                                                                                  |
| ADR-012 | Long-running derivatives, exports, and purges are jobs, not ordinary Vercel request work.                                                                                                                                                                                                                                                                                                                                  | They require retries, idempotency, and recovery from partial failure.                                                                                                                                                                      |
| ADR-013 | Node.js 22 or newer is required. Dependencies are audited before phase gates.                                                                                                                                                                                                                                                                                                                                              | Current Supabase support and current patched dependencies require a modern runtime.                                                                                                                                                        |
| ADR-014 | Authenticated routes render per request and use `private, no-store`; they never use ISR or public response caching. `src/proxy.ts` may refresh sessions and make optimistic `getClaims` checks, but RLS/current membership remains final authorization.                                                                                                                                                                    | A cached refreshed `Set-Cookie` or RSC response can leak one family's session/content to another visitor.                                                                                                                                  |
| ADR-015 | Supabase server clients are created per request; browser clients are unprivileged and caller-scoped. Refresh responses preserve reviewed `Set-Cookie`, `Cache-Control`, `Pragma`, and `Expires` behavior.                                                                                                                                                                                                                  | Warm Vercel instances and shared responses must not carry user state across requests.                                                                                                                                                      |
| ADR-016 | The web deployment has no Supabase secret/service-role credential. A separately deployed narrow worker receives that bypass only after import-boundary, job-integrity, and artifact/secret-scan controls exist.                                                                                                                                                                                                            | A Vercel project environment variable is available to every Function in that project and is not a capability boundary.                                                                                                                     |
| ADR-017 | Every environment declares `OUR_DAYS_ENVIRONMENT` and its expected Supabase project reference; startup/build checks reject Preview→Production, Proof, or mismatched resource references.                                                                                                                                                                                                                                   | Resource separation should fail closed rather than rely on a README promise.                                                                                                                                                               |
| ADR-018 | Until real auth exists, production `/` is a locked invitation-only screen. The approved fixture timeline is available only in development or an explicit local design-review process; external previews require deployment protection.                                                                                                                                                                                     | `robots.txt` and `noindex` are not access control.                                                                                                                                                                                         |
| ADR-019 | The auth phase introduces a nonce-based CSP in the same Next 16 `src/proxy.ts` boundary, narrow origin directives, same-origin mutation tests, and per-action identity/membership/input validation.                                                                                                                                                                                                                        | XSS, CSRF, and hostile direct Server Action/Route Handler calls can expose an otherwise private session.                                                                                                                                   |
| ADR-020 | Every protected page performs its own fail-closed server check before producing a view model; a parent layout repeats the check but is not trusted as the only boundary.                                                                                                                                                                                                                                                   | Next may begin rendering child Server Components before an ancestor redirect resolves, which can place child RSC data in a redirect response.                                                                                              |
| ADR-021 | Journal links set `prefetch={false}` until authenticated cache-isolation tests prove prefetch safe.                                                                                                                                                                                                                                                                                                                        | Private RSC prefetches add browser-resident family payloads and revocation/account-switch cases without enough value for this small app.                                                                                                   |
| ADR-022 | The service worker installs atomically, caches only a fixed versioned public allowlist plus a static locked offline document, never caches runtime navigation responses, and does not call `skipWaiting`.                                                                                                                                                                                                                  | A failed update leaves the previous worker intact, an open draft cannot be silently reloaded, and offline behavior cannot expose journal data.                                                                                             |
| ADR-023 | CI runs with read-only repository permission, immutable GitHub-owned action SHAs, no secrets or shared dependency cache, Linux functional checks for all three browser engines, and x64 macOS 15 pixel comparisons; the first hosted visual run is a reviewed calibration gate, and browser artifacts are not uploaded by default.                                                                                         | Pull-request code gets no privileged context, action tags cannot move underneath a trusted run, local-to-host rendering differences cannot silently rewrite approved evidence, and future traces cannot become a family-data side channel. |
| ADR-024 | Next startup/build validates a typed environment identity and resource mode before loading the app. Unmanaged local work may use detached mode; managed CI declares detached local mode explicitly; hosted Preview/Production require exact HTTPS/site/project bindings, a current publishable key, and a configured denylist of Proof project references. The web process rejects bypass and direct-database credentials. | A wrong project or overpowered credential should stop the process before any route can read family data. This is a decision-independent prerequisite and does not activate Supabase Auth or accept PD-003.                                 |
| ADR-025 | Every repository production-build script is atomic with a redacting scan of tracked source, the complete `.next` tree, and public/browser-deliverable artifacts. Recognized privileged credentials fail in every scope; local design-fixture canaries fail in browser-deliverable scope. All three CI build jobs use those scripts without uploading artifacts.                                                                       | Environment validation prevents known credentials from entering the web process, while artifact scanning detects accidental source/build inclusion and private fixture serialization. Neither control is treated as proof against unknown token formats or external log leakage.                 |
| ADR-026 | Rendered routes use a fresh per-request nonce CSP and request-time rendering. Production forbids unauthorized inline scripts, event handlers, and style attributes; exact configured Supabase HTTP/websocket origins are the only non-self data hosts. Static assets retain a separate header baseline, and HSTS is Production-only.                                                                                            | A private journal favors injection resistance and non-cacheable rendering over static/PPR performance. Exact origins avoid turning future Supabase connectivity into a wildcard exfiltration channel, while environment-scoped HSTS keeps local/Preview testing usable.                           |
| ADR-027 | Invitation links carry the raw one-time secret in the URL fragment. The invite entry immediately exchanges it through a same-origin action for a ten-minute, `HttpOnly`, `SameSite=Strict`, `/invite`-scoped intent cookie and removes the fragment. Code request performs a generic token-plus-email preflight; acceptance reads the cookie server-side and clears it on terminal paths. The database persists only the token hash. | URL fragments are not sent in ordinary HTTP requests or referrers; the short-lived server-only intent survives an iPhone Mail/PWA reload without leaving the secret in React state, form fields, storage, or a normal navigation URL. |
| ADR-028 | Written moments keep `circle_id`, journal person, and recorder immutable. All ordinary writes use narrow RPCs with optimistic revisions; browsers cannot hard-delete. | A family member's journal ownership and the person who recorded a child's memory remain truthful under edits, races, and direct database calls. |
| ADR-029 | Timeline traversal uses a stable occurrence-plus-ID keyset and a fixed snapshot that excludes rows created or updated after traversal begins. Mobile pagination may cumulatively re-read bounded pages for the initial interaction, but must become incremental before scale makes that costly. | Backdated inserts and concurrent edits cannot silently enter an in-progress journey, and equal timestamps do not duplicate or omit memories. |
| ADR-030 | Successful invitation acceptance confirms membership server-side, clears the scoped intent, returns an accepted state, and then uses a full browser replacement navigation to `/family`. | Account switching starts the accepted family in a clean document instead of carrying the previous account's React router tree or leaving the invitation entry in forward history. |
| ADR-031 | MVP places are explicit, trimmed labels stored on the protected moment. The app does not request GPS, infer EXIF location, call a geocoder/map service, or normalize labels into a shared place directory. | A useful “where” should not introduce invisible tracking, third-party disclosure, or false map precision; a private place index can be added later from the same labels. |
| ADR-032 | A membership may keep at most one reaction per moment. Setting another atomically replaces it and selecting none removes it; the interface shows people and words, never aggregate totals. The three stable semantic IDs may receive revised display copy before production. | One quiet response matches the approved interaction and avoids accumulating engagement-style metrics while keeping display wording reversible. |
| ADR-033 | Notes and reaction identities are fetched through a separately authorized, no-store detail action only after a moment is opened; timeline rows never serialize closed conversations. | Family notes are more private than timeline summaries and should not be carried through initial RSC payloads, browser history, or pages the member never opened. |
| ADR-034 | Connected Family Settings may show active account/managed-profile access, minimal pending-invitation metadata, and organizer-only revoke controls. It does not create invitations or receive an email address/raw token until a separate trusted worker can provision the Auth account and deliver the one-time secret. Every mutation is scoped to the server-derived active circle before the database RPC independently rechecks authority. | A raw invite that cannot be delivered safely is a stranded bearer secret. Server-derived circle scoping also prevents a future dual-circle organizer from changing the wrong family while using one circle's UI. |
| ADR-035 | Milestones use a dedicated, authenticated, circle-authorized archive RPC and the established snapshot-plus-keyset journey contract. The Memories landing offers one count-free Milestones doorway beneath On This Day; the route reuses the central timeline and existing moment actions. | A dedicated static query preserves the mature year/anniversary contract, admits a milestone-only partial index, and avoids client filtering or engagement-style archive counts. Reuse keeps milestones visibly part of family history instead of making them a separate feature feed. |

## Product decisions

Before a consuming phase begins, its decision must be `accepted` with approver and date; tests and policies cite that accepted ID.

| ID     | Status                              | Decision                                                                                                                                                                           | Consequence                                                                                                                                                     |
| ------ | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PD-001 | **Accepted — Brian — 2026-08-30**   | Either active guardian may add/edit/trash a managed child's moments; the recorder is preserved.                                                                                    | Children have coherent journals before owning accounts.                                                                                                         |
| PD-002 | **Accepted — Brian — 2026-08-30**   | Adults control permanent deletion of their own moments; organizers manage access, exports, guardians, and managed-child content but cannot silently rewrite another adult's words. | Organizer power does not erase adult authorship.                                                                                                                |
| PD-003 | **Accepted — Brian — 2026-08-30**   | Start with invitation-bound emailed one-time codes/links, with ordinary OTP configured not to create users.                                                                        | Low-friction sign-in without open registration; passkeys can be reconsidered when mature.                                                                       |
| PD-004 | Pending                             | Gate MVP video at one clip per moment and 60 seconds; defer it if the iPhone upload/transcode spike is unreliable.                                                                 | Photo quality is not held hostage by disproportionate video complexity.                                                                                         |
| PD-005 | Pending                             | Use a 30-day private trash; hard purge is worker-only and immediate purge requires explicit authorized intent.                                                                     | Accidental deletion is recoverable while permanent deletion remains available.                                                                                  |
| PD-006 | Pending                             | Issue display derivative URLs for about 60 seconds after a fresh membership check; use authenticated downloads for originals.                                                      | Lower delivery cost with a documented residual derivative-access window; strict immediate revocation remains available via an authenticated proxy if preferred. |
